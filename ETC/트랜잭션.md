
# Transaction

## 1. 트랜잭션이란?

=> 여러 작업을 하나의 작업 단위로 묶어서 전부 성공시키거나, 하나라도 실패하면 전체를 취소하는 것

## 2. 트랜잭션이 필요한 이유

은행 계좌 이체를 예로 들어볼게.

A 계좌에서 B 계좌로 10만 원을 송금한다고 가정하자.

### 송금 전 계좌 상태

| 계좌 | 잔액 |
|---|---|
| A 계좌 | 500,000원 |
| B 계좌 | 200,000원 |

### 10만 원 송금 트랜잭션

1. A 계좌에서 100,000원 차감
2. B 계좌에 100,000원 추가

두 작업이 모두 성공하면 다음과 같다.

### 송금 후 계좌 상태

| 계좌 | 잔액 |
|---|---|
| A 계좌 | 400,000원 |
| B 계좌 | 300,000원 |

그런데 A 계좌에서 10만 원을 차감한 뒤, B 계좌에 추가하는 과정에서 오류가 발생하면 어떻게 될까?

트랜잭션이 없다면 A 계좌의 돈만 줄어드는 문제가 생길 수 있다.

트랜잭션을 사용하면 두 작업을 하나로 묶어서 두 번째 작업이 실패했을 때 첫 번째 작업도 취소할 수 있다.

---

## 3. COMMIT과 ROLLBACK

트랜잭션에서 가장 중요한 두 가지 명령어

| 명령어 | 의미 |
|---|---|
| COMMIT | 트랜잭션의 변경 사항을 확정 |
| ROLLBACK | 트랜잭션의 변경 사항을 취소 |

예를 들어 다음 SQL을 실행한다고 가정하자.

```sql
UPDATE ACCOUNT
SET BALANCE = BALANCE - 100000
WHERE ACCOUNT_ID = 1;

UPDATE ACCOUNT
SET BALANCE = BALANCE + 100000
WHERE ACCOUNT_ID = 2;

COMMIT;
```

두 작업이 성공하면 `COMMIT`으로 확정한다.

반대로 두 번째 작업에서 오류가 발생하면 `ROLLBACK`으로 트랜잭션 시작 이후의 변경 사항을 취소할 수 있다.

### 트랜잭션 실행 흐름

```text
트랜잭션 시작
      ↓
SQL 1 실행
      ↓
SQL 2 실행
      ↓
모든 작업 성공?
      │
      ├── 성공
      │     ↓
      │   COMMIT
      │     ↓
      │   변경 확정
      │
      └── 실패
            ↓
          ROLLBACK
            ↓
          변경 취소
```

단, 이러한 전체 취소는 작업들이 같은 트랜잭션에 속하고, DB가 해당 작업의 롤백을 지원한다는 전제에서 가능하다.

## 4. 트랜잭션의 4가지 특징 (ACID)

| 특징 | 의미 | 설명 |
|---|---|---|
| Atomicity (원자성) | 전부 또는 전무 | 모든 작업이 성공하거나 모두 취소 |
| Consistency (일관성) | 데이터 규칙 유지 | 트랜잭션 전후에 DB의 무결성 제약 유지 |
| Isolation (격리성) | 트랜잭션 간 간섭 제어 | 동시에 실행되는 작업의 영향을 격리 수준에 따라 제어 |
| Durability (지속성) | 결과 보존 | COMMIT된 결과는 장애 후에도 보존 |

## 5. Java에서 트랜잭션 사용

JDBC에서는 `Connection` 객체로 트랜잭션을 관리할 수 있다.

```java
try (Connection conn = dataSource.getConnection()) {

    conn.setAutoCommit(false);

    try {
        // SQL 작업 1
        // SQL 작업 2

        conn.commit();

    } catch (SQLException e) {
        conn.rollback();
        throw e;
    }
}
```

### 핵심 메서드

| 메서드 | 기능 |
|---|---|
| `setAutoCommit(false)` | 자동 커밋 해제 |
| `commit()` | 변경 사항 확정 |
| `rollback()` | 변경 사항 취소 |
| `setAutoCommit(true)` | 자동 커밋 활성화 |

JDBC는 기본적으로 자동 커밋이 활성화되어 있다.

따라서 여러 SQL을 하나의 트랜잭션으로 관리하려면 자동 커밋을 해제하는 것이 일반적이다.

실제 운영 코드에서는 예외 처리와 커넥션 풀의 상태 복원도 고려한다.
